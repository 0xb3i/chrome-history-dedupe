# UI/UX 优化初步方案

## 目标与方向

用户已确认优先场景：通过快捷键打开弹窗，快速找回并打开页面。

本次采用 Impeccable 的 shape 流程组织方案，以 critique 的独立设计审阅与静态检测作为依据。界面属于 Operate 模式，允许大幅调整布局和视觉设计，重点提升扫描效率、键盘操作和反馈清晰度。Ant Design v5 继续作为控件行为与一致性的参考，现有蓝色主色不再作为此次方案的固定约束。

## 视觉约束与建议方向

用户已确认：不用暗黑配色，不用蓝紫配色，不用左侧粗色条强调，保留约 6–8px 的适度圆角。以上新要求优先于项目原有主色约定。

用户进一步指定 Raycast 作为风格参考。v1.2.0 已采用浅色启动器方向：灰白底面、深灰正文、中性灰辅助信息，选中、焦点与关键操作使用中性色；来源色点采用低饱和的绿、棕、玫瑰灰，不再采用此前建议的深青绿主色。

视觉层级主要由字号、字重、间距、对齐与轻量整行背景建立；不使用左侧加粗色条、蓝紫渐变或大圆角卡片堆叠。来源色点保留稳定分组语义，其颜色也遵循新的配色约束。结果列表保持连续阅读，允许重新设计搜索框比例、工具栏布局及列表边界，不必受现有页面排版限制。

v1.2.0 已实现突出搜索框、连续紧凑列表、整行焦点背景、底部键盘提示，以及完整页和改名对话框的配色统一。v1.1.0 的键盘导航、固定搜索区、偏好保护等 UX 继续保留。

方案基于当前源码，未执行真实浏览器测试或截图验收。以下涉及空间和视觉密度的判断需要在后续实施时细化。

## 已有能力

保留 180ms 即时搜索、中文输入法保护、查询与筛选记忆、曾用名高亮、同名分组懒加载及分页、无结果恢复操作。弹窗保持 tab 全局排序，来源标签与稳定色点维持位置一致；完整页继续默认按最近访问展示时间线。

## 弹窗布局草案

从上到下保持四个区域：

1. 紧凑标题栏：历史记录、弱化版本号、完整页入口。
2. 搜索区：全宽搜索框；下一行是时间范围与「仅已命名」。
3. 结果工具栏：左侧结果数，右侧排序和显示选项。
4. 滚动列表：标题优先，来源与访问统计位置稳定；行右侧保留改名、置顶和分组展开入口。

以现有 580px 弹窗宽度和 560px 最大高度作为容量参考，布局与比例可重新设计。采用 4/8/12/16px 间距节奏，标题初步考虑 14–16px、辅助信息 12px、控件高度 32px，圆角保持 6–8px。通过减少重复边界和间距提升密度，不缩小控件点击范围。普通结果优先维持两行；长标题及命中摘要保留必要换行。

默认精简路径展示是建议的新默认：旧用户已保存的显示偏好应继续保留。展开区用于区分链接的必要路径、参数与锚点继续可见。

## 交互边界

- 搜索框 Enter 仍提交查询，不能在用户输入期间隐式打开第一条结果。只有进入结果并聚焦链接后 Enter 才打开页面。
- IME 组合期间不触发导航或打开；对话框与下拉菜单打开时使用各自的键盘语义。
- 列表后台更新后按资源身份保留焦点；当前资源消失时回到邻近结果或搜索框。新查询更新后避免自动抢焦点。
- 置顶及改名操作不应导致滚动位置无故跳动；展开数量与分页遵守已有行为。
- 同名组保留原生链接语义及代表链接选择规则，避免交互控件嵌套；展开状态同步给辅助技术。
- 首次索引加载只展示可确认的操作状态，不虚构百分比或预计完成时间。无结果与读取失败不能共用笼统提示。

## 完整页与改名流程

完整页作为第二优先级，统一搜索、工具栏和结果行样式，保留日期分隔与时间列。备份、恢复和快捷键设置继续位于次级操作区。

改名流程保留取消、还原、空标题验证、保存中禁用及既有持久化语义；补充来源/地址上下文，并为对话框提供正确的可访问名称。

## 检测依据与实施验收

两名独立子代理分别完成设计审阅与机械检测。静态检测在 popup.html、history.html、rename.html 中共报告 16 条 low-contrast 告警，共享样式产生重复记录，不能理解为 16 个独立缺陷。主要涉及弱文字、蓝色 hover 文本及白字蓝色按钮。新版配色需重新检查承载任务信息的文本及具体控件状态；禁用元素与图标需按实际适用标准判断。检测器返回的位置为 line: 0，不能当作准确源码行号。

v1.2.0 已运行 npm run verify，302 项测试、语法检查与 manifest 检查通过。Impeccable 静态检测返回零告警；这不等同于渲染效果验收。按项目约定未启动真实浏览器或截图验收。

建议先完成第一批，让弹窗形成稳定的「输入 → 识别 → 打开」路径，再处理第二批和收尾。方案为初稿，尚未代表用户确认全部交互细节。
